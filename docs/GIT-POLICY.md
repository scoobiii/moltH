# GOS3 Git Policy — Single Source of Truth

**Status:** REQUIRED
**Scope:** all human and agent sessions working on this repository
**Branch:** `main`

## 1. Core rule

`main` is a shared trunk. Before every publication, synchronize first. Never force-push `main`.

## 2. Commit-before-sync

Do not rebase dirty uncommitted work. Commit coherent work or stash it explicitly before synchronization.

## 3. Push gate — ADR-004 + Vortex Enforcement

Push/merge into `main` is allowed only when:

1. local work is synchronized with `origin/main`;
2. TypeScript/lint and build pass;
3. required automated and deterministic tests pass;
4. Vortex Enforcement Gate passes;
5. Deliverable Truth Gate passes;
6. P0 Security/Financial/DREX changes have runtime evidence;
7. P0 changes have independent review and human approval;
8. no unresolved incident/quarantine exists;
9. evidence is generated by execution, not asserted by the LLM;
10. no secret, disguised mock, temporary artifact or bypass flag is staged.

The canonical P0 sequence is:

`INCIDENT → BLOCK/QUARANTINE → CORRECTION → INDEPENDENT REVIEW → CI → COMPLIANCE PASS → HUMAN APPROVAL → MAIN`

## 4. Zero Bypass

Never use `git push --force`, `git push -f`, or `--no-verify`. Never weaken/delete a test merely to make CI pass.

## 5. Multi-session ownership

All sessions follow the same safety policy. No agent has authority to skip the Vortex/GOS3 gate.

## 6. Destructive changes

CREATE, EDIT, DELETE, MOVE, RENAME and REPLACE are all governed operations. Destructive changes must account for consumers, imports, contracts and affected tests before publication.

## 7. P0 domains

`DREX`, `PIX`, `wallet`, `payment`, `banking`, `settlement`, `financial`, `balance`, `account`, `money`, `secret`, `credential`, `authentication`, `authorization` and `security` are P0 when production behavior is affected.

## 8. Truth rule

Compilation is not proof of semantic correctness. A test using a mock is not proof that production is real. If runtime evidence cannot establish the claimed state, the status is `not_verified` and publication is blocked.

## 9. Publication discipline

The GitHub remote is the shared coordination point. Synchronize immediately before publication and stop on conflicts or ambiguous state. Do not discard another session's work.
